# 下一阶段开发计划

排序原则：**先让真实设备跑通，再加新功能**。每一阶段都以「可验证」为出口，
不把未验证的东西标成完成。下表“已有实现”只描述能力与回归入口；当前公开候选结果
统一以 `docs/status.md` 为准。

## P1 · 真实设备接入与加固（需要你配合）

目标：把「模拟验证」变成「真实设备验证」。

| 事项 | 产出 | 依赖 |
| --- | --- | --- |
| 接入实验室 HPC | `@pytest.mark.integration` 的真实集群测试（探测、sbatch 一个 1 分钟作业、日志、取消） | 你的账户 + 允许提交测试作业 |
| 接入 Ubuntu 工作站 | 同上（SSH 执行器真实链路） | 你的 SSH 别名 |
| 解析器对齐 | 用真实 `sinfo/squeue/sacct` 输出替换夹具，修正字段差异 | 上面两项 |
| Slurm 时间上限校验 | 计划阶段比对分区 `MaxTime`，超出直接 `fail` | 真实 `sinfo` |
| 连接复用 | 可选 `ControlMaster`/`ControlPersist`（默认关闭，显式开启） | 无 |
| 断线注入测试 | 提交后断开网络，验证状态恢复与 `lost` 判定 | 可断网环境 |
| Windows + WSL 长作业设备验收 | 已有 Task Scheduler 启动链与离线回归；当前公开候选仍待授权设备验收，尤其 GPU、未登录会话与长作业 | 真实 Windows/WSL 节点 |

| 事项 | 说明 |

## P3 · 资源协调

| 事项 | 说明 |
| --- | --- |
| GPU 队列 | 租约过期 + 等待队列（当前是「冲突即失败」） |
| 预留 TTL | 计划后 N 分钟内未提交自动释放，避免「幽灵租约」 |

## P5 · 服务化与多用户

| 事项 | 说明 |
| --- | --- |
| 常驻控制服务 | 目前是「每次调用一个进程」；服务化后可做后台轮询与通知 |
| 身份与令牌 | 区分「谁提交的」，审计到人；token 只存哈希 |
| 远程 Web API | 在可信网络内暴露，需 TLS + 鉴权 |

## 明确不做（非目标）

- 取代 Slurm / Kubernetes / 任何调度器；
- 在 HPC 上安装常驻 agent 或要求 root；
- 自动配置穿透学校网络的隧道；
- 自动部署项目依赖到系统 Python；
- 大规模数据传输/同步（交给 rsync、Globus、对象存储）。

## 建议的下一步（如果只做一件事）

**接入真实 HPC，跑通一个 1 分钟的 `sbatch` 作业并把日志取回来。**
这一步会把「Slurm 输出解析 + 认证 + 路径 + 分区命名」这些真实世界的差异一次性暴露出来，
比继续加功能更有价值。
