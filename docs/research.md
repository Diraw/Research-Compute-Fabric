# 技术选型与复用边界

本文记录架构取舍，不发布私人机器环境、第三方仓库的过期星标/维护状态，
也不把旧会话中的调研结果当作本次联网核验。依赖版本以 `pyproject.toml` 与 lock 为准；
当前代码/测试是否通过以 [status.md](status.md) 的最终验收记录为准。

## 1. 复用系统已有控制面

| 能力 | 当前选择 | 原因与限制 |
| --- | --- | --- |
| 远程连接 | 系统 OpenSSH | 复用 config、known_hosts、ssh-agent、ProxyJump；仍依赖操作者正确管理主机身份 |
| 集群作业 | Slurm 客户端 CLI | 普通用户可使用既有调度器；不同站点命令、accounting 与配额配置需要实际验收 |
| 状态保存 | Python SQLite | 单机控制面、短事务、易于检查；不是多用户数据库服务或分布式锁系统 |
| 声明配置 | TOML + Pydantic | 类型与交叉引用校验；配置不含秘密字段不等于文件可无审阅公开 |
| CLI / Agent | Typer + MCP Python SDK | 共用服务层与结构化错误；客户端兼容性需按版本验证 |
| 环境 | 已有 Python / venv / Conda / Modules / Apptainer | 探测与计划分离；只在授权的用户前缀内允许变更 |

不引入 SSH 密码数据库、远程 RCF 守护进程或新的调度服务。远端用短命 helper 与普通文件保存
运行证据，调度器节点用 sbatch/squeue/sacct/scancel；不直接 SSH 到计算节点绕过调度器。

## 2. 为什么不直接包一层 sbatch

仅提供 submit/status/cancel 不能回答“代码在哪里”“环境是否匹配”“输出归哪里”或
“提交回复丢失后是否可以重试”。RCF 在命令执行之外增加：

1. 逻辑节点/项目 ID 与实际私有配置分离；
2. 输入、代码与环境证据快照；
3. 可审阅计划与独立确认；
4. 原子提交认领、运行记录、恢复句柄与平台内部 GPU 租约；
5. 产物、进度与存储治理的明确证据边界。

这些机制仍不构成沙箱。项目脚本需要人工审核，SQLite/日志仍可能含敏感数据。

## 3. 外部编排系统只作概念比较

容器集群编排、配置管理、数据管道与科研任务控制面解决的是不同问题。
当前没有为了获得某个概念而引入大型控制服务、容器运行时或远程 agent：

- 需要每节点守护进程或管理员权限的方案，不符合当前最小远程依赖目标；
- 配置管理不能替代 run 的状态、日志、退出码与未知提交恢复；
- 工作流调度不能代替 Slurm 的配额、分区、公平性和分配语义；
- 仅凭项目描述、星标或单次 demo 不能判断安全、许可证或兼容性。

复用第三方源码前必须阅读其当前许可证、来源与具体文件，保留必要归属声明。
本文件不授予任何第三方代码复制权，不推断未审阅项目的许可证或维护质量。

## 4. 需要持续验证的接口

- MCP 当前代码使用 2.x `MCPServer` API；修改下限时同步 lock，并通过真实构造 server、
  `call_tool` 与 CLI/服务映射测试。不按旧 SDK 示例推断接口。
- OpenSSH 与远端 shell 行为有平台差异。合并探测减少连接次数，但不承诺固定延迟；
  主机密钥验证与 BatchMode 不能为了 demo 被关闭。
- Slurm 查询可能延迟、accounting 可能缺失。自己的退出码/状态文件是证据之一，不把查询失败
  或队列消失等同于成功，也不能无条件相信某个单一信号。
- 老系统上的 helper 语法与库 ABI 应用最小解释器单独验证，不从登录节点推断计算节点。
- 网络组网/跳板属于操作者既有基础设施；RCF 不部署隧道，也不替用户修改网络安全策略。

后续架构变化与限制见 [architecture.md](architecture.md)、[security.md](security.md)。
